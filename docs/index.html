SELF-HOSTED DOCKER CONSOLE

Manage your Docker hosts from one console.

Deploy Compose stacks, inspect containers, and switch between Docker hosts. Start with the server and connect agents as you add hosts.

GET STARTED

Install Compose Control

Use a Linux x86-64 host with Bash and curl. If Docker is missing on Ubuntu or Debian, the installer adds Docker Engine and Compose v2 using root or sudo. On other Linux distributions, have Docker Engine and Compose v2 ready. The agent uses openssl to generate its access token.

Use PowerShell on Linux or on Windows with Ubuntu on WSL 2 and systemd. On Windows, the installer runs inside Ubuntu and keeps the deployment files in its Linux home directory.

Use a trusted network. Both services mount the Docker socket and can administer their host. Restrict access to a trusted network or VPN, use HTTPS for the console over the network, and allow only the server to reach the agent port.
01

Start the server

Run on the Docker host that will run the web console.

BASHView installer ↗
(installer=$(mktemp) && trap 'rm -f -- "$installer"' EXIT && curl -fsSL https://raw.githubusercontent.com/stoxello/Compose-Control-Releases/main/install.sh -o "$installer" && bash "$installer" server)
POWERSHELLView installer ↗
& ([scriptblock]::Create((Invoke-RestMethod 'https://raw.githubusercontent.com/stoxello/Compose-Control-Releases/main/install.ps1' -ErrorAction Stop))) server

The installer creates compose-control-server/ with the server Compose file. On that host, open http://localhost:8080 and follow the first-run wizard to create the administrator account. From a trusted machine on the network, use the server hostname in place of localhost or open your configured HTTPS address.

02

Connect another Docker host

Run on each additional host you want to manage.

BASHView installer ↗
(installer=$(mktemp) && trap 'rm -f -- "$installer"' EXIT && curl -fsSL https://raw.githubusercontent.com/stoxello/Compose-Control-Releases/main/install.sh -o "$installer" && bash "$installer" agent)
POWERSHELLView installer ↗
& ([scriptblock]::Create((Invoke-RestMethod 'https://raw.githubusercontent.com/stoxello/Compose-Control-Releases/main/install.ps1' -ErrorAction Stop))) agent

The installer creates compose-control-agent/ with the agent Compose file and a private .env file.

  1. In the server console, open Environments and find Connect a Docker host.
  2. Enter a name and an address the server container can reach, such as http://AGENT_HOST:5151.
  3. Open compose-control-agent/.env privately on the agent host. Paste the COMPOSE_CONTROL_AGENT_TOKEN value into Access token and choose Add environment.
  4. Use the environment selector at the top of the console to switch to the agent.

Re-running the install commands reuses your existing Compose files and agent token.

IN THE CONSOLE

Work with your stacks

Choose a host

The environment selector controls where you browse resources and deploy stacks. Select This host for the server's local Docker engine.

Deploy a stack

Open Stacks to view existing projects or create one from a Compose definition. Browse the app catalog to start from a template.

Inspect a workload

Open Containers to view container status and logs. Open a stack to see its containers and manage its lifecycle.

MAINTENANCE

Update and troubleshoot

Run the command for your service from its installation directory. The default image tags are latest.

Server update

docker compose -f compose.yaml pull && docker compose -f compose.yaml up -d

Agent update

docker compose -f compose.agent.yaml pull && docker compose -f compose.agent.yaml up -d
Set up WSL 2 on Windows

Install Ubuntu on WSL 2 and verify that systemd is enabled. Run the PowerShell command on Windows. If you need to connect from another machine, configure WSL networking for the server or agent port.

Change the listening port

Set COMPOSE_CONTROL_PORT for the server or COMPOSE_CONTROL_AGENT_PORT for the agent in the .env beside its Compose file. Run docker compose -f FILE up -d again with the corresponding filename and use the new port when connecting.

Find out why an agent cannot connect

Check http://AGENT_HOST:5151/health from the server's network. If the agent won't start, run docker compose -f compose.agent.yaml logs --tail=100 in the agent directory. For authentication errors, check that the token in the console matches the agent's .env.

Find the files to back up

Preserve data/, keys/, and stacks/ on the server. On each agent, preserve its .env, agent-replicas/, agent-docker-config/, and stacks root. Back up the volumes and bind mounts used by your deployed apps separately.
